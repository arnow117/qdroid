# Research baseline and evidence limits

Research date: 2026-10-22. Imported summary: 2026-10-23. These are public-source facts and engineering inputs; no robot, account integration or Linux isolation backend was validated during the research.

## Established inputs

- T1 Pro is the first planned device. The [official specification](https://www.primebot.com/product_spec1.html) lists Orin Nano and secondary-development SDK for Pro.
- The reviewed [T1 SDK](https://github.com/PrimebotTech/primebot-t1-sdk/tree/a460300013003b29b9ad291b1b857b0afe295b22) uses ROS2/FastDDS. Its public PlayEmotion contract provides MP4 file playback with absolute paths, priority and loop count. This does not establish actual player-board file access, codec profile, progress or clear behavior.
- Public touch docs identify T-series back/chest sensors and contain broad event enums alongside a more conservative note. Initial binding must use actual observed device events.
- NVIDIA documents [software encoding on Orin Nano](https://docs.nvidia.com/jetson/archives/r36.5/DeveloperGuide/SD/Multimedia/SoftwareEncodeInOrinNano.html), which has no NVENC. On-device rendering needs real resource measurements.
- [Jetson Linux 36.5](https://developer.nvidia.com/embedded/jetson-linux-r365) uses the 5.15 baseline, while the inspected [OpenShell support matrix](https://docs.nvidia.com/openshell/latest/about/support-matrix) required Landlock ABI 3 and additional qualification. Actual device backports/configuration must be probed; ARM64 support alone is insufficient.
- gVisor documents [ARM64/Linux requirements](https://gvisor.dev/docs/user_guide/install/), [platform choices](https://gvisor.dev/docs/user_guide/platforms/), [rootless-mode differences](https://gvisor.dev/docs/user_guide/rootless/) and [application/limit compatibility](https://gvisor.dev/docs/user_guide/compatibility/). No specific T1/gVisor/Chromium combination was tested.
- Rootless Docker's [resource-limit prerequisites](https://docs.docker.com/engine/security/rootless/tips/) must be tested; accepted configuration flags are not enforcement evidence.

## Reuse candidates

- [pi agent-core](https://github.com/earendil-works/pi/blob/main/packages/agent/README.md): agent loop/model/tool interfaces; qdroid still owns external authorization and execution isolation.
- [DeepSeek Harness architecture](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/architecture.md): plugin composition reference. Its [safety statement](https://github.com/deepseek-ai/deepseek-harness/blob/master/SAFETY.md) identifies developer-preview and isolation limitations.
- [HyperFrames](https://github.com/heygen-com/hyperframes): HTML/seekable-animation-to-MP4 under Apache-2.0; [determinism](https://github.com/heygen-com/hyperframes/blob/main/docs/concepts/determinism.mdx) depends on explicit time, frozen resources and versions.
- [Agent Skills specification](https://agentskills.io/specification): portable instructions/resources, not an OS permission standard.
- [MCP security best practices](https://modelcontextprotocol.io/docs/2026-07-28/tutorials/security/security_best_practices): local server compromise, SSRF, downstream token separation and proxy authorization risks.

## Lark CLI

The inspected stable release was [v1.0.98](https://github.com/larksuite/cli/releases/tag/v1.0.98), including Linux ARM64 artifacts. The inspected main snapshot was `017b19a793ad71794a02887ede04757f3d82e10d`.

- [Build configuration](https://github.com/larksuite/cli/blob/017b19a793ad71794a02887ede04757f3d82e10d/.goreleaser.yml): Go executable variants, with CGO disabled in that snapshot.
- [Extension API](https://github.com/larksuite/cli/blob/017b19a793ad71794a02887ede04757f3d82e10d/extension/README.md): credentials, transport, command restrictions and audit extensions.
- [Sidecar documentation](https://github.com/larksuite/cli/blob/017b19a793ad71794a02887ede04757f3d82e10d/sidecar/server-demo/README.md): separate `authsidecar` build, sentinel credentials, same-host proxy, HMAC, and demo limitations including refresh behavior.
- [Transport implementation](https://github.com/larksuite/cli/blob/017b19a793ad71794a02887ede04757f3d82e10d/extension/transport/sidecar/interceptor.go): requests without sentinel credentials can follow a separate path; direct downloads require explicit policy.

The official demo is not a production qdroid broker. A host/identity allowlist does not restrict all semantic API effects; per-operation/resource authorization and replay/refresh/usage handling are qdroid requirements.

## Local media experiment

A controlled offline HTML page with explicit state/time rendering produced a two-second H.264/yuv420p video on Mac ARM64. Matching state/time produced matching PNG hashes, and different states changed the image. Chromium's own sandbox setting was retained; the command needed an execution-permission adjustment in the development tool.

This demonstrates only the local media pipeline. It does not validate T1 display compatibility, Jetson performance, a Linux ARM64 dependency image, gVisor compatibility, account isolation, or physical safety. The experiment's machine-specific paths and personal development configuration are intentionally not copied into this public project.

## Freshness and licensing

Versions above are dated evidence, not instructions to install latest. Implementation must pin and recheck actual selected versions. The T1 repository's GitHub license metadata was unrecognized; this does not establish redistribution rights. Vendor SDK/firmware, tool binaries, fonts, media and FFmpeg build choices require separate license/provenance verification.
